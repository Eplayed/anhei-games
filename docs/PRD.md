## 一、产品目标

### 1.1 产品定位

暗黑破坏神玩家导航站是一个面向暗黑破坏神系列（Diablo 2/3/4）玩家的垂直导航网站，旨在为玩家提供一站式资源入口。

### 1.2 解决的核心问题

1. **资源分散问题**：玩家需要在多个攻略站、工具站、论坛之间来回切换，缺乏统一入口
2. **信息获取效率低**：游戏更新、赛季信息、蓝帖等内容分散在不同平台
3. **新手入门门槛高**：新玩家不知道哪些攻略站和工具值得使用
4. **工具查找困难**：各类计算器、模拟器等工具链接分散，难以记忆

### 1.3 产品价值

- **聚合价值**：将分散的资源统一聚合，提供分类清晰的导航
- **效率价值**：玩家快速找到所需攻略、工具和最新资讯
- **社区价值**：成为中文暗黑玩家常用入口，建立用户习惯
- **零成本维护**：纯静态站点，无需后端，维护成本极低

### 1.4 成功指标

| 指标 | 目标值 |
|------|--------|
| 日活跃用户(DAU) | 500+ |
| 平均停留时长 | 2分钟+ |
| 返回率 | 30%+ |
| 核心链接点击率 | 60%+ |

## 二、用户故事

### 用户故事 1：赛季开荒玩家
**角色**：暗黑破坏神4赛季玩家  
**场景**：新赛季开始后，想快速找到最新开荒攻略  
**故事**：作为一名赛季玩家，我希望打开导航站就能看到各大攻略站的最新开荒Build推荐，这样我就不需要分别打开MAXROLL、Icy Veins等网站逐个查找。  
**验收标准**：首页展示各攻略站的最新开荒攻略链接，按职业分类

### 用户故事 2：装备掉落查询
**角色**：暗黑破坏神3休闲玩家  
**场景**：刷本时掉落了一件装备，想查询掉落位置和用途  
**故事**：作为一名休闲玩家，我希望通过导航站快速访问掉落查询工具，这样我就能快速判断这件装备是否值得保留。  
**验收标准**：工具区提供D3Planner、掉落查询等工具的快速入口

### 用户故事 3：关注游戏更新
**角色**：暗黑破坏神全系列忠实玩家  
**场景**：想知道游戏最近有什么更新或官方动态  
**故事**：作为一名忠实玩家，我希望在导航站看到最新的官方更新公告和蓝帖摘要，这样我就不需要分别访问官网和Twitter。  
**验收标准**：新闻区展示最新的官方公告、更新日志、蓝帖

### 用户故事 4：新手入门引导
**角色**：暗黑破坏神系列新玩家  
**场景**：刚入手游戏，不知道如何开始  
**故事**：作为一名新玩家，我希望导航站能提供新手入门指南和推荐资源，这样我就能快速上手游戏。  
**验收标准**：提供新手专区，包含入门攻略、基础概念解释、推荐YouTuber/B站UP主

### 用户故事 5：Build规划与模拟
**角色**：暗黑破坏神硬核玩家  
**场景**：想规划下个赛季的Build，需要模拟伤害和配装  
**故事**：作为一名硬核玩家，我希望通过导航站快速打开Build模拟器，这样我就能提前规划赛季Build。  
**验收标准**：工具区提供D3Planner、Maxroll D4 Planner等模拟器的直接入口

### P0 - 核心功能（必须有）

| 编号 | 需求 | 描述 | 优先级理由 |
|------|------|------|-----------|
| P0-1 | 攻略社区导航 | 聚合MAXROLL、Icy Veins、Diablo Fans、Reddit等主流攻略社区链接 | 核心价值，用户最主要需求 |
| P0-2 | 工具集合导航 | 提供D3Planner、掉落计算器、Build模拟器等工具链接 | 核心价值，玩家高频使用 |
| P0-3 | 新闻资讯入口 | 展示官网公告、赛季信息、更新日志的入口链接 | 核心价值，玩家关注游戏动态 |
| P0-4 | 按游戏版本分类 | 内容按Diablo 2/3/4分类展示，用户可选择对应版本 | 避免信息混杂，提升体验 |
| P0-5 | 响应式布局 | 适配桌面端和移动端，移动端可添加为PWA | 现代网站基础要求 |
| P0-6 | 搜索功能 | 站内搜索，快速定位目标资源 | 提升使用效率 |

| 编号 | 需求 | 描述 | 优先级理由 |
|------|------|------|-----------|
| P1-1 | 最新攻略推荐 | 首页展示各攻略站最新热门攻略（可通过RSS或手动更新） | 提升内容时效性，增加回访 |
| P1-2 | 中文资源专区 | 聚合中文攻略站、B站UP主、贴吧等中文社区 | 服务中文玩家，差异化价值 |

| P1-5 | 暗黑风格UI | 采用暗黑破坏神系列视觉风格（暗色主题、哥特字体） | 增强沉浸感，符合产品调性 |
| P1-6 | PWA支持 | 支持添加到手机桌面，离线访问 | 提升移动端体验 |

| 编号 | 需求 | 描述 | 优先级理由 |
|------|------|------|-----------|
| P2-1 | 每日一言/小贴士 | 展示游戏冷知识或实用技巧 | 增加趣味性，提升停留时长 |
| P2-2 | 社区热门讨论 | 聚合Reddit、贴吧等平台的热门讨论 | 增加内容丰富度 |

## 四、UI设计稿

### 4.1 整体风格

**设计风格**：游戏原版UI风（复古怀旧），参考暗黑破坏神2/3/4的原版界面设计
- 字体：使用像素字体或衬线字体（如 Diablo font、Gothic字体）
- 边框：复古浮雕边框，模仿游戏内UI边框
- 按钮：游戏原版按钮样式，带纹理背景
- 配色：暗金色(#c8860a) + 深灰背景(#1a1a1a) + 血红色(#8b0000)点缀

**色彩方案**：
- 主背景色：`#1a1a1a`（深灰色）
- 卡片背景：`#2d2d2d`（深灰）
- 主强调色：`#c8860a`（暗金色，呼应暗黑稀有装备配色）
- 次强调色：`#8b0000`（血红色，点缀用）
- 文字主色：`#e0e0e0`（浅灰白）
- 文字次色：`#8a8a8a`（中灰）
- 链接悬停色：`#f0a030`（橙金色）

**字体方案**：
- 标题：使用哥特风格字体（如 `Diablo`, `Gothic` 或像素字体）
- 正文：系统默认无衬线字体
- 代码/数据：等宽字体

### 4.3 核心页面设计

#### 4.3.1 首页（All Games Overview）

- **Hero区域**：大标题"暗黑破坏神玩家导航"，副标题"一站式资源入口"
- **游戏版本快速入口**：D2/D3/D4 三个卡片式入口，点击进入对应版本专属页面
- **热门资源推荐**：展示全站点击量最高的资源链接
- **最新更新**：展示最近添加或更新的资源

#### 4.3.2 攻略社区页（按游戏版本）

- **顶部Tab切换**：D2 / D3 / D4
- **攻略站卡片列表**：
  - 每个攻略站为一个卡片
  - 卡片包含：网站Logo/图标、名称、简介、标签（如"Build推荐"、"掉落查询"）
  - 点击卡片跳转到对应网站
- **分类筛选**：按内容类型筛选（Build攻略、装备指南、赛季指南等）

#### 4.3.3 工具集合页

- **工具卡片网格布局**：2列或3列卡片布局
- **每个工具卡片包含**：
  - 工具名称
  - 适用游戏版本标签（D2/D3/D4）
  - 功能描述
  - 直达链接按钮
- **搜索框**：快速搜索工具名称或功能

#### 4.3.4 新闻资讯页

- **资讯源列表**：
  - 官方公告（Battle.net）
  - 更新日志（Patch Notes）
  - 蓝帖（Blue Posts）
  - 社区新闻
- **展示形式**：列表式，每条显示标题、来源、时间、摘要
- **点击跳转**：跳转到原始新闻页面

### 4.4 组件规范

#### 卡片组件
```
┌─────────────────────────┐
│  🔗 图标   资源名称      │
│  简短描述文字           │
│  标签1  标签2           │
│           [访问网站 ->] │
└─────────────────────────┘
```
- 卡片悬停效果：边框发暗金色光晕
- 卡片圆角：8px
- 卡片阴影：0 4px 12px rgba(0,0,0,0.5)

#### 按钮组件
- 主要按钮：暗金色背景，悬停时亮度提升10%
- 次要按钮：透明背景+暗金色边框
- 链接按钮：文字链掗，悬停时加下划线

#### 导航组件
- 顶部固定导航栏，滚动时始终可见
- 移动端变为汉堡菜单

## 六、技术方案概述

### 6.1 技术栈

- **前端框架**：Vite + Vue 3 + Tailwind CSS
- **UI组件库**：Element Plus（适配暗黑风格）
- **路由管理**：Vue Router
- **数据存储**：JSON文件存储资源数据（静态导入）
- **构建工具**：Vite
- **部署方案**：Vercel / GitHub Pages
- **PWA**：Vite PWA Plugin（Service Worker + Web App Manifest）

## 八、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 资源链接失效 | 用户体验下降 | 定期检查链接有效性，添加"报告失效"功能 |
| 新闻内容更新不及时 | 内容时效性差 | MVP阶段只提供链接入口，不做内容聚合 |
| 移动端体验不佳 | 失去移动用户 | 开发阶段优先考虑响应式设计 |
| 维护成本高 | 项目难以持续 | 采用JSON数据驱动，降低内容更新成本 |
